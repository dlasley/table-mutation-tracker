The scraper exposes a small HTTP API for the n8n orchestrator. It is not a public API: there is no published host, and the interactive playground is turned off for that reason. The endpoint pages in this section are generated from the FastAPI app's OpenAPI spec.

| Endpoint | Called by | Purpose |
| --- | --- | --- |
| `POST /scrape` | Scheduled workflow | Scrape the portal and return normalized JSON |
| `POST /append-index` | Scheduled workflow, after commits | Add one snapshot to the rolling index |
| `POST /rebuild-index` | Workflow fallback on 409 | Recompute the rolling index from every snapshot |
| `GET /health` | Monitoring, deploys | Confirm required configuration is present |

## Authentication

Every `POST` endpoint requires a shared secret in the `X-Webhook-Secret` header. The scraper compares it in constant time against its `WEBHOOK_SECRET` environment variable. A missing or wrong value returns 401.

```bash
curl -X POST https://scraper.example.com/append-index \
  -H "X-Webhook-Secret: $WEBHOOK_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"date": "2026-06-05", "time": "153000"}'
```

`/health` needs no secret and reveals only which variable names are missing.

## Response conventions

All three `POST` endpoints report unexpected failures in the response body with HTTP 200 and `"status": "error"`, so n8n can branch on the result without treating it as a transport error. The error body carries the exception message and an `error_id`. The scraper logs the full stack trace to stdout with the same `error_id`, so you can search the logs for it. The response never includes the trace. The one exception is the `/append-index` out-of-order case, which returns 409 (see below).

<ResponseExample>
```json /scrape success
{
  "status": "success",
  "data": { "...": "normalized classes and assignments" }
}
```

```json /rebuild-index success
{
  "status": "success",
  "snapshots": 85,
  "total_changes": 268
}
```

```json Error
{
  "status": "error",
  "error": "Authentication failed: Auth cookie not found after login. Credentials may be invalid. Current URL: https://sis.example.com/...",
  "error_id": "3f9a1c7d0b2e"
}
```
</ResponseExample>

`/append-index` also uses HTTP status codes, including 409 for the one condition the workflow acts on:

| Status | Meaning |
| --- | --- |
| 200 | Entry appended or replaced, and the body includes the new `entry`. Any other failure also returns 200, with `"status": "error"`. |
| 401 | Missing or invalid secret. |
| 409 | Snapshot is older than the newest index entry. The body's `detail.status` is `needs-rebuild`. |
| 422 | Request body is not valid JSON with `date` and `time`, `date` is not `YYYY-MM-DD`, or `time` is not six digits (`HHMMSS`). |
| 500 | Scraper is missing `GITHUB_TOKEN` or `DATA_REPO`. |
