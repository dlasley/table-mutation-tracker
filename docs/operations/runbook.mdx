Commands run from the repository root unless noted. Python uses a virtual environment in `.venv`.

<Warning>
  Every live scrape logs in to the real portal, which sits behind bot detection. None of the procedures on this page scrape. Avoid triggering the n8n workflow manually unless you need to.
</Warning>

## Set up a development environment

<Steps>
  <Step title="Install Python dependencies">
    ```bash
    python -m venv .venv
    .venv/bin/pip install -r requirements.txt -r requirements-dev.txt
    .venv/bin/playwright install chromium
    ```
  </Step>
  <Step title="Run the tests">
    ```bash
    .venv/bin/python -m pytest
    ```
    Tests use an in-memory snapshot store and never contact GitHub or the portal.
  </Step>
  <Step title="Run the frontend">
    ```bash
    cd frontend
    npm install
    npm run dev
    ```
    Copy `frontend/.env.local.example` to `frontend/.env.local`, fill in a read-only GitHub token and the data repo, and add `DATA_PREFIX=synthetic` to read test data.
  </Step>
</Steps>

## Deploy the scraper

The scraper runs as a container on AWS App Runner. Automatic deployments are off, so pushing an image does not deploy it.

<Steps>
  <Step title="Check the class configuration">
    The image copies `config/sources.json` from your working tree. The file is not in Git; confirm it exists and is current.
  </Step>
  <Step title="Build for amd64 and push">
    App Runner runs on amd64. Apple Silicon builds arm64 by default, so set the platform explicitly.

    ```bash
    aws ecr get-login-password --region us-east-1 \
      | docker login --username AWS --password-stdin <account>.dkr.ecr.us-east-1.amazonaws.com
    docker buildx build --platform linux/amd64 \
      -t <account>.dkr.ecr.us-east-1.amazonaws.com/table-scraper:latest --push .
    ```
  </Step>
  <Step title="Deploy">
    ```bash
    aws apprunner start-deployment --region us-east-1 --service-arn <service-arn>
    ```
  </Step>
  <Step title="Verify">
    ```bash
    curl https://<scraper-host>/health
    ```
    Expect `{"status":"ok"}`. A 500 lists any missing environment variables. The health check does not contact the portal or GitHub.
  </Step>
</Steps>

## Rebuild the rolling index

Rebuild after changing the diff logic, or when the index has drifted from the snapshots. Run it locally rather than through `/rebuild-index`: a full rebuild can outlast the container platform's request timeout.

```bash
GITHUB_TOKEN=$(gh auth token) .venv/bin/python scripts/rebuild_index.py
```

The script reads every snapshot, diffs consecutive pairs, and overwrites `index/rolling_index.json`. Add `--synthetic` to rebuild the test data index instead. Save a copy of the current index first if you want to compare before and after:

```bash
gh api repos/<owner>/<data-repo>/contents/index/rolling_index.json \
  -H "Accept: application/vnd.github.raw" > rolling_index.before.json
```

## Rotate the webhook secret

The secret lives in two places that must match.

<Steps>
  <Step title="Generate a new value">
    ```bash
    openssl rand -hex 32
    ```
  </Step>
  <Step title="Update the scraper">
    Set `WEBHOOK_SECRET` in the App Runner service's environment variables. Saving the change redeploys the service.
  </Step>
  <Step title="Update n8n">
    Edit the Header Auth credential used by **Scrape Tables**, **Append Index**, and **Rebuild Index Fallback**. All three pick up the change because they share the credential.
  </Step>
  <Step title="Verify without scraping">
    Call `/append-index` with the newest snapshot's date and time. Re-appending an existing snapshot recomputes its index entry in place, so it is safe.

    ```bash
    curl -X POST https://<scraper-host>/append-index \
      -H "X-Webhook-Secret: <new-secret>" \
      -H "Content-Type: application/json" \
      -d '{"date": "2026-06-05", "time": "153000"}'
    ```
    Expect HTTP 200. The old secret should now return 401.
  </Step>
</Steps>

## Generate test data

`scripts/generate_synthetic.py` writes realistic, randomized snapshots under the `synthetic/` prefix of the data repo, then builds a matching index. Vercel preview deployments read this data.

```bash
GITHUB_TOKEN=$(gh auth token) .venv/bin/python scripts/generate_synthetic.py --days 14 --clean
```

| Flag | Effect |
| --- | --- |
| `--days N` | Generate N days ending today (1 to 60) |
| `--start-date`, `--end-date` | Generate an explicit range instead of `--days` |
| `--clean` | Delete existing synthetic data first |

## Update the API reference

The API reference is generated from the FastAPI app. After changing an endpoint, regenerate the spec:

```bash
.venv/bin/python scripts/export_openapi.py
```

A test fails if `docs/openapi.json` is out of date.
